A harness is the agent CLI a bot runs in. bothub supports two, picked by the bot's `harness`:
**opencode** and **pi**. Both talk only to the LiteLLM proxy, where a bot's `model` is an alias,
so which tokens pay for a run is a proxy setting and not a harness choice.

An adapter does two pure things: build the command line for a <Sym name="RunSpec" />, and turn
each line of the harness's JSON output into normalised agent events. The
[runner](/docs/reference/runner) does the spawning.

The primary harness. Tools are a real allowlist, including patterned bash like
`bash(git diff*)`, and the bothub MCP server is mounted through `OPENCODE_CONFIG_CONTENT`.

Light and fast. Tools are all or nothing and it has no MCP client, so it suits read-only bots. A

## Without a model

`bothub sim` swaps every adapter for a scripted one, so whole workflows run with no model at all.
See [Sim](/docs/reference/sim).
