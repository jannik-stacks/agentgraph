`dispatch.ts` decides which jobs an event starts. `pipeline.ts` runs them: in dependency order,
each in a fresh worktree, each bot job looping until its checks pass, and each finishing with a
closure that tells the jobs after it whether to go on.

## Planning

<Sym name="plan" /> matches an event against every workflow's triggers. Text written by people is
only accepted from trusted associations unless a trigger's `guard` says otherwise.
<Sym name="dispatch" /> wraps it with the store's delivery ledger, so a redelivered webhook plans
nothing.

## Running a plan

<Sym name="runPlan" /> goes workflow by workflow. A job starts only when every job it needs closed
`done` or `handed-off`, and it starts from the branch and pull request they handed off. A job of the
same event that already closed is reused, and a job with an `environment` waits for approval.

## The until loop

`attempts` is the heart of a bot job. It runs the bot, reads its proposals, and when the job has
`until`, runs each check against the worktree. Failing findings go back to the same bot as a
follow-up prompt. After `until.max` follow-ups, or once the bot's `usd-per-run` is spent, the run
fails, every proposal but `ask` is held back, and bothub adds an `ask` that names the failing checks.
