## How one event flows

```
BotEvent → dispatch → runPlan → runPlanned → attempts → runJob (harness) → checks → validate → apply
```

An event comes from a webhook, a watched issue file or the CLI and is normalised into a
<Sym name="BotEvent" />. <Sym name="dispatch" /> plans the jobs it starts, <Sym name="runPlan" />
runs them in dependency order, and each bot job loops through attempts until its checks pass.
Proposals from the final attempt are validated and applied, and everything lands in the
[run store](/docs/reference/store).
