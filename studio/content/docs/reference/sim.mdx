`bothub sim <scenario>` runs a hub against a scripted human action. Bots are replaced by a scripted
harness, checks by scripts that pass or fail as the scenario says, and everything else is real:
dispatch, the pipeline, the MCP server, validation and apply on a temporary copy of the hub. The
acme-app example keeps its scenarios in `examples/acme-app/sims`.

<Sym name="simulate" /> copies the hub, applies the human action through the local issues backend,
dispatches the change, runs the jobs and prints a trace from the event to the changed issue files.
With faults it also crashes and restarts mid-run, reconciles, and delivers the event twice.

## The scripted harness

`sim-harness.ts` is a standalone program the sim adapter starts in place of opencode or pi. It
reads its steps, calls hub tools through a small MCP client, and prints agent events.
